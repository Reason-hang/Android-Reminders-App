## 架构不变量

- `ADVANCE`、`DUE`、`SNOOZE` 独立，只有 `DUE` 推进重复周期。
- 事件、操作和超时均按 `reminderId + alarmId + kind + occurrenceTime` 隔离。
- Service 管理强提醒媒体与会话；Activity 只负责展示和用户交互。
- 系统通知是后台全屏页的唯一启动者；App 不从后台自行启动 `AlarmActivity`，也不在通知前主动唤醒屏幕。
- `triggerTime` 是重复模板，`nextTriggerTime` 是实际下一次时间。
- Room 与 AlarmManager 使用补偿式一致性，不假设跨系统事务。
- 不增加网络能力，不提交 APK、签名文件、密钥或本机配置。

## 接手顺序

1. 阅读 [README](../../README.md)、[产品需求文档](../01-产品文档/01-产品需求文档.md) 和 [AI 自主决策记录](./01-AI自主决策记录.md)。
2. 执行 `git status -sb` 与 `git log -1 --oneline`，以当前 Git 状态覆盖本文可能过期的信息。
3. 目标手机已连接；解锁后优先执行 [真机验收清单](../05-测试与验收/02-真机验收清单.md)，先覆盖锁屏 ADVANCE→DUE。
4. 真机失败时先在诊断中心开启增强诊断并导出 ZIP，再记录设备锁屏状态、权限状态、SystemUI 的 BAL 日志、录屏和复现时间。
5. 代码变化后重新执行 JVM、仪器源码编译、Lint、Release 构建、APK 元数据和文档链接检查。
