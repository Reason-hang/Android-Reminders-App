## 实际命令

```bash
JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home \
ANDROID_HOME=/opt/homebrew/share/android-commandlinetools \
./gradlew testDebugUnitTest :app:compileDebugAndroidTestKotlin \
  --rerun-tasks --console=plain --warning-mode=none
```

```bash
JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home \
ANDROID_HOME=/opt/homebrew/share/android-commandlinetools \
./gradlew lintDebug assembleRelease \
  --rerun-tasks --console=plain --warning-mode=none
```

v1.12 以 JDK 17 实际执行：`testDebugUnitTest`（100/100）、`compileDebugAndroidTestKotlin`、`assembleDebugAndroidTest`、单线程 `lintDebug` 与单线程 `assembleRelease` 均退出码 0。首次组合执行在 Dex 合并阶段长时间无输出，主动终止并停止残留 Daemon 后，各任务独立执行全部通过，不能把被中断的组合任务写成失败或通过。

ADB 覆盖安装后确认 `versionName=1.12`、`versionCode=13`。用户明确授权 `SYSTEM_ALERT_WINDOW` 后，专用仪器测试 1/1 通过；窗口、截图、诊断事件和清理事件一致。随后真实 ADVANCE、DUE 和延迟 10 分钟的 SNOOZE 再次验证相同路由。最终 Release 覆盖安装会把 Debug 版本授予的悬浮 AppOp 重置为 `ignore`，已依据用户本次明确授权重新设为 `allow` 并读回确认。

首次将 Lint 与 Release 放在同一并行 Gradle 调用中时，Android Lint 读取了被 Release 重建的 KAPT 临时 stub，出现 Lint 内部异常；拆分为串行单线程任务后恢复通过。这是构建竞态，不是本次源代码规则错误。
