## 前置条件

1. 已安装 v1.12 构建产物，确认版本为 `1.12 (13)`。
2. 开启通知、锁屏全屏提醒、解锁悬浮强提醒、锁屏显示、自启动和省电无限制；系统闹钟音量大于 0。
3. 分别记录测试前的屏幕开关、Keyguard 锁定、App 前后台和权限状态。
4. 每个场景保存触发时间、kind、logcat 和截图或录屏。

## 核心场景

| 编号 | 场景 | 预期 |
|---|---|---|
| A1 | 锁屏正式到点 | 开启声音/震动配置后，声音、振动、高优先级通知；系统通过 FullScreenIntent 允许时亮屏和全屏 |
| A2 | 屏幕关闭且 Keyguard 已锁定 | 完整强提醒稳定出现 |
| A3 | 屏幕关闭但尚未进入安全锁 | 记录实际横幅或全屏结果，不与 A2 混为同一状态 |
| A4 | 已解锁并正在使用手机 | 权限开启时显示可交互应用悬浮强提醒页，声音、振动正常；诊断包含 `overlay_shown`，不得只显示横幅 |
| A5 | App 后台或划掉最近任务 | 提醒仍能触发 |
| A6 | 提前 5 分钟后保持解锁至到点 | ADVANCE 和 DUE 分别显示新悬浮页并重新响铃、振动；旧实例不得吞掉 DUE |
| A7 | 提前后重新锁屏再到点 | DUE 应重新投递锁屏强提醒 |
| A8 | 两条提醒同一分钟 | 后一条成为当前打断，前一条保留静音通知 |
| A9 | 点击旧通知操作 | 不得停止或修改当前新实例 |
| A10 | 声音与振动四种组合 | 只执行用户开启的媒介，始终保留视觉提醒；两者关闭时诊断必须为 `not_requested`，不得写为已播放 |
| A14 | 保留通知点击 | 自动结束或关闭后的通知进入提醒列表，不进入编辑页 |
| A15 | 诊断来源 | 系统全屏、通知点击、闹钟图标分别具有正确 `launchSource`；旧记录不被判定为已自动全屏 |
| A16 | 并发接管与停止来源 | 后续提醒接管旧实例时产生 `alert_preempted`；关闭、划掉、稍后、完成和页面操作各自记录来源 |
| A17 | 悬浮权限撤销 | 解锁态记录 `overlay_failed=permission_missing`，首页提示开启，提醒退化为系统通知但媒体与服务不中断 |
| A11 | 关闭 | 停止当前打断并保留静音通知 |
| A12 | 稍后 10 分钟 | 当前打断结束，10 分钟后独立 SNOOZE，不跳过 DUE |
| A13 | 完成或删除 | 一次性和重复范围语义正确 |

## 十分钟自动结束

| 编号 | 场景 | 预期 |
|---|---|---|
| T1 | 全屏提醒后不操作 10 分钟 | 铃声、振动、前台服务和全屏页结束，App 不再主动保亮，保留静音通知 |
| T2 | 解锁悬浮强提醒不操作 | 10 分钟后移除悬浮页、停止媒体和前台服务，并记录 `overlay_dismissed` 与 `timer_expired` |
| T3 | ADVANCE 后 5 分钟到 DUE | DUE 重置自己的 10 分钟计时；ADVANCE 的旧超时不能关闭 DUE |
| T4 | 两条不同提醒连续触发 | 旧提醒超时不能停止新提醒 |
| T5 | 9 分钟时手动关闭 | 立即停止；第 10 分钟不得产生二次关闭或影响后续提醒 |

普通第三方 App 不强制执行系统关屏。T1 的“恢复熄屏”验收为：全屏页关闭、`FLAG_KEEP_SCREEN_ON` 不再生效，屏幕随后按 Android/HyperOS 系统超时策略熄灭。

## 采证命令

```bash
ADB=/opt/homebrew/share/android-commandlinetools/platform-tools/adb
$ADB devices -l
$ADB shell getprop ro.product.model
$ADB shell getprop ro.build.version.sdk
$ADB shell dumpsys package com.reminder.local | grep -E 'versionName|versionCode'
$ADB logcat -c
$ADB logcat -v threadtime | grep -E 'com.reminder.local|Background activity launch|BAL'
```

优先在 App 内开启增强诊断并导出 ZIP；同时保留录屏、设备状态和触发时间。若诊断仅有 `alarm_scheduled`，先比对 `triggerAt`，未到点不是故障。锁屏页面未显示时检索 FullScreenIntent/SystemUI；解锁页面未显示时检查 `overlayAllowed` 和四个 overlay 事件。v1.12 不应出现由 `com.reminder.local` 主动发送 `AlarmActivity` 的 BAL 错误。系统 Logcat 可作为补充，但不能替代应用私有诊断包。

## 已获得的真机证据

- 2026-08-11 v1.9：锁屏 ADVANCE 到点后，系统日志为 `com.android.systemui:full_screen_intent`，`AlarmActivity` 成为前台窗口，页面层级显示“提前提醒”；旧版的 BAL 阻断未再出现。
- 同日 DUE：21:05 到达 Receiver 和前台服务，正式通知为 `importance=4`、`category=alarm`、`PUBLIC` 且带 `fullscreenIntent`；测试中切换应用并在 21:10 发生第二条提醒接管，不能作为 DUE 页面显示或 T1/T3 自动结束的通过证据。
- 2026-08-12 v1.10/v1.11：v1.10 的 19:54、19:56、19:58 DUE 与 20:00 ADVANCE 均到达 Receiver、前台服务并投递携带 FullScreenIntent 的通知；v1.11 的 20:12 DUE 同样成功，SystemUI 记录为 pinned Heads-up，未进入 AlarmActivity。被测提醒保存的声音/震动均关闭，不能作为媒体验收。解锁态横幅符合 SystemUI 策略，不能以此判定后台投递失败。
- 2026-08-12 v1.12：专用悬浮层仪器测试 1/1 通过，设备窗口和截图确认整页可见；真实 ADVANCE 和 DUE 均记录 `overlay_shown`，启用的声音和震动实际启动。21:03:16 从真实 DUE 点击稍后，21:13:16 独立 SNOOZE 准时触发并再次显示悬浮整页、响铃和震动，21:13:47 从悬浮页关闭，A4、A6、A12 已取得通过证据。仍需补 A1-A3、A5、A7-A11、A13-A17、T1-T5。
